# Cloud.ru S3 — проект требований

## Участники

Владелец согласовывает требования и предоставляет настройки целевого бакета.
Пользователь загружает фото, получает результат, просматривает карточку и удаляет аккаунт.
Оператор разворачивает сервисы и при необходимости переносит существующие объекты.
Статус — checkpoint 1 подтверждён владельцем сообщением «подтверждаю».

## Функциональные требования

- FR-1 MUST. API и recognizer работают с приватным Cloud.ru S3 по параметрам
  S3_ENDPOINT, S3_REGION, S3_BUCKET, S3_ACCESS_KEY, S3_SECRET_KEY, S3_FORCE_PATH_STYLE.
  При валидных настройках оба сервиса используют один бакет и одинаковую схему подписи.
  При отсутствующей или некорректной обязательной настройке старт завершается ошибкой.
- FR-2 MUST. Полный путь фото поддерживает запись оригинала, чтение оригинала,
  запись нормализованной копии, проверку существования и подписанный GET.
  Проверка — загруженные байты совпадают при чтении, Content-Type сохраняется.
- FR-3 MUST. Удаление по сроку, удаление аккаунта и уборка осиротевших объектов
  используют Cloud.ru. Подтверждённое отсутствие объекта считается успехом,
  отказ доступа или сетевой сбой передаётся вызывающему коду.
  Проверка — сбой удаления сохраняет возможность повторного выполнения.
- FR-4 MUST. Уборка осиротевших объектов обрабатывает все страницы ListObjectsV2.
  Проверка — объект на второй странице также достигает существующей логики уборки.
- FR-5 MUST. Основной Compose получает внешние параметры S3 и запускает приложение
  с подготовленным бакетом. Локальный MinIO остаётся доступным для изолированных тестов.
  Проверка — конфигурация Cloud.ru разрешается без административных реквизитов MinIO.
- FR-6 MUST. Оператор получает env-пример, инструкцию подключения и переноса старых фото.
  Существующие object_key и normalized_object_key сохраняются.
  Проверка — документ описывает копирование с проверкой байтов до переключения приложения.
- FR-7 MUST. OpenSpec хранит proposal, design, сценарии и задачи этой доработки.
  Проверка — openspec validate cloudru-s3 --strict завершается успешно.

## Нефункциональные требования

- NFR-1. Приватность бакета и существующие проверки владения действуют для каждого фото.
  Ссылки фотографий для клиента проходят через существующие серверные маршруты.
- NFR-2. Конфигурация SDK учитывает контрольные суммы Cloud.ru по образцу clipmkr.
- NFR-3. Секреты задаются через окружение API и recognizer.
- NFR-4. Unit-тесты выполняются без внешнего доступа к Cloud.ru.
  Живой тест отмечается отдельно и требует доступного целевого бакета.

## Границы и зависимости

Доработка включает адаптер хранения, env, Compose, регрессионные проверки и инструкции.
Текущий запрос авторизует подготовку и реализацию изменения в рабочей копии.
Переключение работающего стенда и перенос пользовательских фото оформляются отдельной операцией
после определения источника, целевого бакета и способа проверки переноса.
Зависимости — доступ к S3 Cloud.ru для живой проверки, Node 22 для разработки,
Docker с PostgreSQL и MinIO для полного интеграционного набора.

## Исходные данные

clipmkr commit d35c15bdbf3f01e4188d4a7494f06bc021b38906 содержит параметры
https://s3.cloud.ru, ru-central-1, S3_FORCE_PATH_STYLE=false и формат ключа tenant_id:key_id.
Пример предполагает отдельный бакет tarelka. Реальные реквизиты и имя предоставляет владелец.
