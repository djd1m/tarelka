# ADR-001 — Использовать общий AWS S3 клиент

## Status

Implemented in working copy. Требования подтверждены владельцем.
Реализация проверена локальными тестами, живое подключение Cloud.ru требует реквизитов.

## Context

API и recognizer выполняют все операции с приватными фотографиями через MinIO SDK.
Cloud.ru требует согласованных endpoint, региона и адресации для подписи запросов.
В clipmkr уже есть образец настройки AWS SDK для этого провайдера.

## Decision Drivers

- Высокий приоритет имеют корректная подпись и доступ к приватному бакету.
- Высокий приоритет имеет повторяемое удаление персональных данных при сбоях.
- Средний приоритет имеет локальная проверка с MinIO.

## Considered Options

1. Добавить region/pathStyle ко всем экземплярам MinIO SDK.
   Плюс — небольшое изменение зависимостей. Минус — четыре копии настройки клиентов,
   другой транспорт относительно проверенного в clipmkr образца.
2. Использовать общую фабрику AWS SDK и существующие интерфейсы сервисов.
   Плюс — единая подпись и настройки checksum из clipmkr.
   Минус — добавляются зависимости AWS SDK и требуется проверка совместимости с MinIO.

## Decision

Выбрать вариант 2. Общий пакет экспортирует createPhotoS3Client.
StorageConfig содержит обязательные region и forcePathStyle.
API и recognizer проверяют S3_REGION, S3_FORCE_PATH_STYLE и origin S3_ENDPOINT при старте.
SDK использует WHEN_REQUIRED для request/response checksum и maxAttempts 3.
Объекты адресуются существующими ключами без префикса нового приложения.
DeleteObject передаёт ошибки, HEAD возвращает false только для HTTP 404.
Листинг использует paginateListObjectsV2 и передаёт ошибки вызывающему коду.
Общий deletePhotoS3Object перед каждой операцией удаления проверяет GetBucketVersioning.
Enabled и Suspended отклоняются. Ошибка чтения состояния также отклоняет удаление.
При подготовке Cloud.ru используется бакет, на котором версионирование никогда не включалось.
Маршрут POST /scans перехватывает и журналирует ошибки cleanup откатанной попытки,
сохраняя ответы 202 для повтора, 429 для квоты и 503 для сбоя БД.

## Consequences

Все четыре клиента используют единые настройки. Runtime использует заранее созданный бакет.
MinIO SDK остаётся зависимостью тестовой оснастки на период изменения.
Ошибки доступа при HEAD перестают трактоваться как отсутствие объекта.

## Confirmation

- tests/unit/s3-storage.test.ts проверяет реальные HTTP-запросы SDK, подпись,
  GET/PUT/HEAD/DELETE, ошибку доступа, отсутствующий объект и пагинацию листинга.
- tests/unit/config.test.ts проверяет обязательность и формат региона,
  адресации и endpoint для обоих сервисов.
- tests/integration/check-env-wiring.test.ts проверяет проброс новых параметров.
- tests/unit/scans-cleanup.test.ts проверяет ответы 202/429/503 при отказе cleanup.
- tests/unit/s3-storage.test.ts проверяет отказ удаления при Enabled, Suspended
  и недоступном GetBucketVersioning, а также успешное повторное удаление.

## Revisit

Пересмотреть при смене провайдера или добавлении браузерной прямой загрузки.
