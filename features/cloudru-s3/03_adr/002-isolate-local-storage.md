# ADR-002 — Изолировать локальный MinIO профилем Compose

## Status

Implemented in working copy. Изоляция подтверждена разрешением Compose и локальными тестами.
Запуск полного PostgreSQL/MinIO набора требует Docker daemon.

## Context

Приложение сейчас зависит от storage и storage-init в Compose.
MinIO root-пароли интерполируются даже при использовании внешнего S3.
Интеграционные тесты создают и удаляют объекты и требуют отдельного хранилища.

## Decision Drivers

- Высокий приоритет имеет запуск Cloud.ru без административных реквизитов MinIO.
- Высокий приоритет имеет изоляция интеграционных тестов от пользовательских фото.
- Средний приоритет имеет сохранение существующих команд test-профиля.

## Considered Options

1. Удалить MinIO и направлять проверки на Cloud.ru.
   Плюс — одна система. Минус — внешняя зависимость и риск записи в production-бакет.
2. Выделить локальное хранилище в отдельный compose-файл.
   Плюс — чистое разделение конфигурации. Минус — меняются команды существующих тестов.
3. Оставить MinIO в профилях test/local-storage и убрать зависимость приложения от него.
   Плюс — сохраняется способ запуска тестов. Минус — нужны runtime-проверки локальных секретов.

## Decision

Выбрать вариант 3. API и recognizer получают S3_* из окружения и зависят только от БД.
storage/storage-init запускаются профилями test и local-storage.
Локальные секреты интерполируются пустыми, shell перед запуском требует непустые значения.
Production API проверяет обязательные S3_* в загрузчике конфигурации.
Сервис test всегда использует http://storage:9000, us-east-1, path-style true
и отдельные N4_S3_* реквизиты.
ensureBucket существующего интерфейса проверяет HeadBucket подготовленного бакета.
Создание Cloud.ru бакета и перенос файлов выполняет оператор по инструкции.
Инструкция требует бакет с никогда не включавшимся версионированием
и право GetBucketVersioning для runtime-ключа.

## Consequences

Cloud.ru-профиль не требует MinIO root-секретов.
Локальный тестовый запуск требует N4_STORAGE_ROOT_* и N4_S3_*.
Бакет Cloud.ru должен существовать до старта обработки фото.
Старые ключи сохраняются, проверенное копирование предшествует переключению приложения.

## Confirmation

- tests/unit/s3-compose.test.ts проверяет Cloud.ru config без MinIO-секретов,
  профили и отдельные test-реквизиты.
- tests/unit/s3-storage.test.ts проверяет HeadBucket без CreateBucket.
- docs/operations/cloudru-s3.md содержит копирование с проверкой байтов,
  остановку записи на переключении и обратное переключение на исходное хранилище.

## Revisit

Пересмотреть при выделении тестовой инфраструктуры в отдельный репозиторий.
