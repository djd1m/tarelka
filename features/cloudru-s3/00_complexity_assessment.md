# Cloud.ru S3 — оценка сложности

Task kind: feature

## Источник процесса

По запросу владельца применяется feature-adr 1.5.26 из djd1m/dz-harness,
commit 6bd2a4601fb0b819a65c81fba0ad2b9c5a123a29.
Режим reference. OpenSpec 1.15.0 контролирует дельту требований.
Статус — уровень L подтверждён владельцем сообщением «подтверждаю».

## Классификация

| Измерение | Баллы | Основание |
|---|---|---|
| Файлы | 3 | Ожидается 11–30 файлов кода, конфигурации и тестов |
| Домены | 2 | Одна интеграция хранения, API и воркер используют общий адаптер |
| Интеграции | 2 | Cloud.ru Object Storage через S3 API |
| Совместимость | 2 | Меняется конфигурация production-хранилища |
| Модели данных | 1 | Используются существующие object_key в PostgreSQL |
| Сквозные аспекты | 2 | Проверка настроек и передача ошибок хранилища |

Сумма — 12, числовая оценка M. Применён предусмотренный router override
для миграции инфраструктурной интеграции — L. Изменение затрагивает все операции
с фотографиями и требует отдельной проверки удаления персональных данных.

## Этапы и проверки

Активны шаги 0, 1, 2, 3, 3.5, 4, 5, 6, 7, 8, 9.
Оценка времени по router — до двух часов активной работы, доступ к Cloud.ru
и ожидание контрольных точек учитываются отдельно.
После согласования требований — исследование, ADR, оценка рисков независимыми
агентами, модель хранения, архитектура и план. Перед кодом — проверки K1/K2.
После кода — тесты, независимое ревью, fleet QE и проверка соответствия OpenSpec.

## Доступные инструменты

Исследованы исходники tarelka и clipmkr. Реализацию выполняет текущая модель Codex.
На этапах независимой проверки используются отдельные агентные сессии.
Выбор доступных моделей и фактические запуски фиксируются в отчётах соответствующих этапов.
На старте окружение содержит Node 18 и npm 9, Docker CLI отсутствует.
Для CLI OpenSpec и проверок проекта требуется Node 22.
Учётные данные Cloud.ru в рабочую копию не передавались.
