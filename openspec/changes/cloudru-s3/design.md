## Context

Требования и уровень L подтверждены владельцем.
Текущие четыре MinIO-клиента используют одинаковые ключи из PostgreSQL.
Образец Cloud.ru взят из packages/s3/src/client.ts проекта clipmkr.

## Goals

Все операции фотографий используют Cloud.ru S3 с явным регионом и адресацией.
Локальные интеграционные тесты используют собственный MinIO.
Ошибки удаления доступны существующей логике повторов.

## Decisions

- ADR-001 в features/cloudru-s3/03_adr выбирает общую фабрику AWS SDK,
  checksum WHEN_REQUIRED, явный region и forcePathStyle.
- ADR-002 изолирует MinIO профилями test/local-storage.
- Параметры S3 проверяются в env.ts обоих сервисов.
- Существующие интерфейсы операций и ключи объектов сохраняются.
- Runtime проверяет подготовленный бакет через HeadBucket.
- Удаление проверяет GetBucketVersioning и отклоняется при Enabled/Suspended
  либо недоступном состоянии. Для фото выделяется бакет без истории версионирования.
- Cleanup откатанной попытки скана журналирует ошибки с сохранением ответов 202/429/503.

## Risks

Отказ подписи проверяется HTTP-тестами с реальным SDK, затем живым smoke при наличии ключей.
Пагинация проверяется двумя страницами списка.
Отказы доступа и транспорта передаются обработчикам удаления.
Переключению старых фото предшествует копирование с проверкой байтов и краткой остановкой записи.

## Migration

Создать приватный бакет с никогда не включавшимся версионированием и выдать runtime-права
GetObject/PutObject/DeleteObject/ListBucket/GetBucketVersioning.
Скопировать объекты с исходными ключами, проверить содержимое и Content-Type.
На переключении остановить запись, досинхронизировать, проверить и задать S3_* в окружении.
Исходный бакет остаётся доступным для обратного переключения.

## Verification

Unit-тесты, transport fixtures, env wiring, разрешение Compose, typecheck, lint,
сборки пакетов, независимое review и fleet QE. Живой Cloud.ru smoke требует реквизитов.
